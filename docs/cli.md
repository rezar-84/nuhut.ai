# Command reference

Every command of the runtime (`.ai-sdlc/bin/sdlc.py`) and the installer (`install.sh`).
Each runtime command also explains itself with examples: `python3 .ai-sdlc/bin/sdlc.py <command> -h`.

## The runtime: `python3 .ai-sdlc/bin/sdlc.py <command>`

Grouped the way `sdlc.py --help` groups them:

| Group | Commands |
| --- | --- |
| Start here | `status` |
| Records and checks | `doctor`, `verify`, `finish`, `approvals`, `bite`, `plan-check`, `ci-check` |
| Viewer and reports | `view`, `lens`, `audit`, `metrics` |
| Work items and agents | `item`, `hotfix`, `next-id`, `render`, `merge-shard`, `claim`, `unclaim` (`release`, deprecated), `claims`, `parallel`, `dispatch`, `trailers`, `sync`, `review`, `log`, `guard`, `mcp` |
| Releases and deploys | `deploy record`, `deploy list` |
| Specs | `spec` |
| Writing | `slop` |
| Setup | `config`, `notify`, `fix`, `ext` |
| Extension commands | `issues pull`, `issues push` (the `github-issues` built-in) |

Global options: `--root <dir>` runs against another project; `--selftest` checks the
runtime itself. Exit codes: `0` success, `1` a check failed (with `--strict`) or an action
was refused, `2` a usage error.

| Command | Key Flags | Description |
| --- | --- | --- |
| **`status`** | `--json` | One screen of what to do next on this branch, read-only. It opens with the setup this clone is missing, each with its fix: a merge driver `.gitattributes` asks for that is not configured (`fix merge-driver`), an identity that is unset or that `docs/project/people.json` does not know (`NUHUT_USER`, else `git config user.name`), and `gh` missing or not logged in while open Tier 1 items exist. Then your items, which are the claims on this branch or worktree or held by you, plus an item named in the branch name. For each it gives the next step it owes (`plan`, `build`, `verify`, `review`, `log`, `finish`, or `release` for a claim on a finished item), using the same rules `finish --dry-run` uses. Then items Parked or Blocked on you, Ready items you could take (`parallel`'s list, and those that need a plan first), and the doctor finding count. Always exits `0`. Joining a project: [joining.md](joining.md). |
| **`doctor`** | `--strict`, `--baseline`, `--all`, `--json` | Audits project records, active roles, check commands, staleness windows, and validates the dependency graph (flags self-dependencies, non-existent backlog IDs, and circular dependency loops). Ages the backlog against the same window: an `In progress` or `In review` row nothing has named since the window passed is a zombie claim; a `Ready`, `Blocked` or `Parked` row older than the window needs a decision. Every finding says how to fix it and who can: a command (`tool`), your agent (`agent`), or you (`owner`); `--json` carries them as `fix` and `who`. What each item owes follows its tier: a Tier 3 item's commit is its whole record.<br>`--baseline` accepts today's findings in `docs/project/doctor-baseline.json`, so an old project can turn on `--strict` in CI and see only new problems. Doctor and the viewer still say how many are accepted, and since when. Once the file exists, a rewrite only drops fixed findings and never adds one. A leaked credential is never accepted. `--all` lists the accepted ones.<br>With a `docs/project/people.json` registry (read from the default branch) it warns about an open item whose owner is neither a role nor a handle (one line per owner), an Approvers entry that is not a handle (a name it knows is told the handle to write), and gives one count of claims that record no person. |
| **`verify`** | `--item <ID>`, `--parallel` (`-j`), `--stage`, `--timeout` | Runs the charter's check pipeline in order, writing immutable test evidence (`summary.md`, `summary.json`, and stage `.log` files) to `.ai-sdlc/evidence/<timestamp>/`. `--item` names the work item in the ledger rows. A clean tagged run counts for the item once one of the item's commits is in its history; a run made with uncommitted changes counts when the item's next commit is made on top of it. Uncommitted records (`<docs>/project/**` other than the charter) and `.ai-sdlc/` state do not make a run dirty. `--stage` records the selected stages in the ledger, and a `--stage` run never satisfies `finish`. `--parallel` runs independent steps concurrently using a worker pool. |
| **`finish <ID>`** | `--waive verify --by <name> --reason "…"`, `--dry-run` | Closes a built item in one step, checking only what its tier owes:<br>- a full `verify` run (every charter stage that has a command, no `--stage`) made clean on the item's newest code commit or a descendant of it, or dirty on that commit's parent (not at Tier 3). Records-only commits (ledger, worklog, status) do not make a run stale. A partial run and a stale run each get their own message<br>- or a waiver: recorded as *Not run*, never Verified, and not allowed at Tier 1. `--by` must name someone in the charter's **Approvers** row as it stands on the default branch (`origin/<default>`, else `<default>`), so a branch that adds a name gains nothing until it merges; a blank Approvers row refuses every waiver. The ledger records `waived_by` and `waived_as`, the identity running the command: `NUHUT_USER`, else `git config user.name`, mapped through `people.json` when there is one. With no terminal attached, the waiver is refused unless that identity is the named approver. `NUHUT_USER` is an honour-system value that any process, an agent's included, can set. A waiver stops counting once its approver leaves the row, and `finish` says so<br>Commits belong to the item only through a `Work-Item: <ID>` trailer (`sdlc.py trailers <ID>`); a mention in the subject or body does not attribute a commit.<br>- a ship review at Tier 1, and an independent review where the charter asks for one<br>- `plan-check`, when there is a plan<br>Then it drafts the worklog entry from git and the ledger (the compact line for Tier 3 under Strict, and for Lean Tier 2), marking what only the agent knows `TODO(finish)`, and refuses until those are written. Last it moves the row to Done, or to **Parked** at Tier 1 for the human merge approval. It also refuses while a review finding is escalated to a person with no decision in the review's Responses table. Exit `1` lists each thing still owed with the command that supplies it. On an item already Done it only drafts a missing worklog entry. |
| **`approvals <ID>`** | `--json` | Who approved the item's merge, read-only. With `gh` on PATH and signed in, it reads the item branch's pull request (`gh repo view` for the repository, then `gh pr view <branch> --repo <owner/name> --json reviews,number,headRefOid,author,state,...`, 20 s timeout). The PR counts only when it is this repository's own (not cross-repository), open or merged, and its head is the local item branch (a merged PR also counts when its head is on the default branch and contains the item's newest commit); otherwise the note says `pr-mismatch`. Each reviewer's latest verdict counts when it is `APPROVED` on the head commit, from a login other than the PR author and not a bot, that `people.json` on the default branch maps to a handle. Anything else is listed as ignored with its reason (`stale`, `self-approval`, `bot`, `unmapped`, `changes-requested`, `dismissed`, `invalid-login`). Without `gh`, on a gh error, or with no matching PR, the charter's **Approvers** handles are reported with `source: charter`. `AI_SDLC_APPROVAL` is never read. Tier 1 needs 2, Strict Tier 2 needs 1, and any other item needs none (it says `no approval required at Tier 2 under Standard tier rules`, reads no PR and exits `0`); when Approvers lists fewer people it says `1 of 2: this project lists 1 approver`. `finish` uses the same result: met, the item goes to Done and the shard's `approvers` records `{handle, login, source, commit, at}`; not met, it stays Parked. Exit `0` met, `1` not met, `2` not in the backlog. |
| **`guard start\|stop`** | | The finish guard, run by Claude Code's SessionStart and Stop hooks (reads the hook JSON on stdin). When the agent stops, it names a Tier 1 or 2 item this session committed that is not Done or Parked, once per item, and asks for `finish`. It never blocks a tool call. The installer registers it for Claude Code (`--no-finish-guard` to skip; `--upgrade --finish-guard` to add it later), and the charter's **Finish guard** row turns it off. |
| **`plan-check <ID>`** | `--base REF`, `--strict`, `--pre`, `--json` | Compares branch changes against the approved plan (`docs/project/plans/<ID>.md` or `.sdlc/specs/<ID>/spec.md`). Highlights unapproved file modifications and planned files left untouched with ANSI terminal colors, and warns when the plan's paths match over half the repository. Counts `.ai-sdlc/bin/`, `profile.json` and `manifest.json`; other `.ai-sdlc/` state is ignored. `--strict` exits `1` on any of these gaps. `--pre` runs before the build and exits `1` when a planned path matches no file and is not marked `(new)`, or the list is too broad. |
| **`ci-check`** | `--base REF`, `--head REF\|event`, `--charter-ref REF`, `--json` | Judges a pull request: the commits in `merge-base(base, head)..head`, merge commits included (a merge is judged on what it brings in against its first parent). It fails a commit without `Work-Item`, or without both `Agent` and `Model` unless it says `Agent: human`, or with the value `unknown` (bots `dependabot[bot]` and `github-actions[bot]` skip this rule only). It fails an item whose committed ledger record is not a full, current verify run (`finish`'s rule; it checks the record, not the result), a Tier 1 item with no review file, a commit whose paths match a Tier 1 glob while its item is Tier 2 or 3, an item whose tier is lower than in the base branch's backlog, and an item with no backlog row. The Tier 1 globs are the backticked globs in the charter's **Always Tier 1 here** row, read at `--charter-ref` (default: the default branch); with none there, `auth/`, `migrations/` and `infra/` at any depth. `.ai-sdlc/**` (not its generated state or `test-lock.txt`), `.github/workflows/**` and `people.json` always count, and the charter counts when a security-bearing row changes. `--base` defaults to the charter's Default branch, else `main`; `--head` to `HEAD`; `--head event` reads `pull_request.head.sha` from `$GITHUB_EVENT_PATH`. Records (backlog, ledger, reviews) are read from the working tree. Exit `0` clean, `1` findings, `2` a usage error or a shallow clone (check out with `fetch-depth: 0`). |
| **`view`** | `--serve`, `--port`, `--host`, `--allow-actions`, `--interval`, `--github`, `--no-user`, `--export-html <file>`, `--svg`, `--no-open`, `--json` | Draws the project as one interactive page ([the viewer](viewer.md)): Inbox, Board, Dashboard, Blockages, Git, Documents, Project. `--serve` keeps it live on `127.0.0.1` and lets it run commands and change kit settings; `--github` adds open issues and PRs; `--no-user` hides `~/.claude` items. `--host tailscale` (this machine's Tailscale IPv4), `--host <ip>` or `--host 0.0.0.0` makes it reachable from other machines: each start prints a link with a new access key (`/?k=<key>`), every request needs that key or the cookie it sets, any other Host is accepted, and the page is read-only unless you also pass `--allow-actions`. A bind outside Tailscale's `100.64.0.0/10` warns that traffic is plain HTTP. `--host` and `--allow-actions` need `--serve`. `--export-html` writes one offline file. |
| **`lens`** | `--area stack\|deps\|build\|security\|deploy\|env\|agents\|standards`, `--write`, `--user`, `--json` | The **Project lens**, read-only:<br>- the stack, detected live<br>- direct dependencies per manifest, with lockfiles<br>- `file:line` errors from the latest failing verify stages<br>- security: vulnerable packages from the last `audit`, doctor's sensitive-data findings, a committed or un-ignored `.env`, container risks, open security-review findings<br>- deployment platforms, CI workflows and containers (Dockerfiles, compose services)<br>- environment variable **names** (templates vs code; values are never read)<br>- the agentic stack: skills, commands, subagents, hooks, MCP servers, plugins, harness files and other kits; `--user` adds `~/.claude`<br>- `--area standards`: the conventions the code already follows (formatter and linter configs, naming style per language, test layout, import style, the commit convention from `git log`); `--write` drafts `<docs>/project/standards.md` and never overwrites one that exists |
| **`spec list\|show\|validate\|apply`** | `apply <ID> [--write]`, `validate [--strict]`, `--json` | Living specs, when the charter's **Specs** row is on (`config --specs on`).<br>- `docs/project/specs/<capability>.md` holds requirements (SHALL/MUST) with WHEN/THEN scenarios.<br>- An item that changes behaviour adds `specs/changes/<ID>.md` (ADDED / MODIFIED / REMOVED).<br>- `apply` merges it on close (exact names only, a dry run without `--write`) and archives it.<br>- An existing `openspec/` folder and Spec Kit specs are read beside them, read-only.<br>- Shown under Documents ▸ Specs and in each item's thread. |
| **`slop [paths]`** | `--strict`, `--guide`, `--json` | [The slop filter](slop-filter.md): lists the phrasings that make prose read as machine-written, by file and line, with a fix for each. With no path it scans the prose files changed against `HEAD`; `-` reads standard input.<br>- strong tells (chatbot leftovers, `not just X, but Y`, inflated significance, unnamed experts) count on one sighting<br>- moderate tells (stock vocabulary, `serves as` for `is`) count in clusters<br>- weak tells (dashes, groups of three) are reported only when dense<br>Exit `1` when a file fails and either `--strict` is given or the charter's **Slop filter** row is `strict`. Code, link targets, quoted lines and lines marked `slop-ok` are skipped. No model call. |
| **`item add\|set\|show\|list\|triage`** | `--title`, `--type`, `--tier`, `--effort`, `--touch`, `--depends`, `--status`, `--discovered`, `--hotfix`, `--sync-refs`, `--json` | Manages per-item JSON shards under `docs/project/items/<ID>.json` so parallel worktrees never collide on `backlog.md`. `item add` allocates the next ID automatically when `<ID>` is omitted; `--discovered` and `item triage <ID>` enforce the charter's **Discovered defects** policy (`Parked`, or `Ready` for a Tier 2–3 defect with a passing `bite` run when `Auto-Ready (bite)` is active). `item set <ID> --hotfix` marks a hotfix (see `hotfix`). `--owner` takes a role slug or, when `docs/project/people.json` lists people, a person's handle (a name or GitHub login it knows is stored as the handle); anything else is refused. Without a registry the owner is kept as written. |
| **`hotfix <ID>`** | `--json` | The documented shortcut for `item set <ID> --hotfix`, through the same code. Records `hotfix: true` and the UTC time on the item; the tier stays. `finish` then skips the pre-merge review (verify, escalations and Tier 1's human approval still apply) and records `retro_review: owed`. The retroactive review is `docs/project/reviews/<ID>-retro-<role>.md` (`review <ID> --stage retro`); `doctor` fails the hotfix when it is missing after the charter's **Retroactive review within** (default 2 days). `doctor` also fails a postmortem whose **Follow-up items:** ID is not a work item, and warns when it names no regression test. |
| **`next-id`** | `--kind item\|adr`, `--sync-refs`, `--json` | Allocates the next work item (`PREFIX-001`) or ADR (`0001`) identifier atomically via `<git-common-dir>/nuhut/seq.json`, and with `--sync-refs` pushes a compare-and-swap commit chain to `refs/nuhut/seq` on `origin`. |
| **`render`** | `--check`, `--json` | Materialises `backlog.md` and `worklog.md` summary views from `items/*.json` and `worklog/*.md` shards; `--check` exits `1` when either summary file is out of sync. |
| **`merge-shard BASE OURS THEIRS`** | `--marker-size N` | The `nuhut-shard` git merge driver for `docs/project/items/*.json`; git runs it as `merge-shard %O %A %B`. A 3-way merge per field: a field only one side changed takes that change; `history` entries from both sides are kept; other lists (`touch`, `depends`) keep both sides' additions and either side's removals; `tier` takes the stricter value (Tier 1 over 2 over 3). `approvers`, `waivers`, `status`, `hotfix` and `owner` changed differently on both sides are written as conflict markers and never merged automatically, so a revoked approver stays revoked and a status never moves forward through a merge. Any other field both sides changed goes to the side with the newer `updated`; a stamp more than 5 minutes ahead of the clock is ignored, and a tie is a conflict. Exit `0` merged, `1` conflict markers written, `2` a file was unreadable or not one item's JSON, and the file is left unchanged. The installer writes the `.gitattributes` line; `fix merge-driver` turns it on in a clone. |
| **`claim <ID>`** | `--agent`, `--worktree PATH`, `--no-worktree`, `--base REF`, `--mark`, `--sync-refs`, `--json` | Takes a work item. Writes an atomic claim to `<git-common-dir>/nuhut/claims/` (and with `--sync-refs` pushes a parentless CAS ref to `refs/nuhut/claims/<ID>` on `origin`), creates `<type>/<ID>-<slug>`, and by default opens a worktree at `../<repo>-<ID>`. The claim records the agent, the host and the person: `NUHUT_USER`, or `git config user.name` when `people.json` maps it, stored as the handle. When neither gives one it records `person: null`, never a guess, and warns once (inside the result with `--json`); an unknown agent is warned about the same way. `claims`, `doctor` (one count of claims without a person) and the viewer (*unknown person*) show it. With the charter's Worktree scripts row set, it runs setup in that worktree with `NUHUT_ITEM` and a per-worktree `NUHUT_PORT`, and exits `1` when setup fails (the claim is kept). |
| **`unclaim <ID>`** / **`claims`** | `--agent`, `--force`, `--remove-worktree`, `--sync-refs`, `--json` | Frees a claimed item (verifying `agent`, which defaults to your trailer identity, and `host` unless `--force`), or lists active local and remote claims. With `--sync-refs` ownership is checked against the remote lease and the ref is deleted with `--force-with-lease`; a stale local record is dropped and the remote lease left alone. `--remove-worktree` runs the Worktree scripts teardown first; a failing teardown releases nothing unless `--force`. |
| **`release <ID>`** (deprecated) | as `unclaim` | The old name of `unclaim`. It does the same thing with the same stdout, `--json` output and exit codes, and prints one line on stderr that repeats your arguments under the new name (`release: deprecated, use: sdlc.py unclaim ACME-12 --remove-worktree`). It is removed in 7.0. |
| **`deploy record`** | `--version <v>` and `--env <env>` (required), `--from <ref>`, `--to <ref>` (default `HEAD`), `--by <name>`, `--dry-run`, `--json` | Records that a version runs in an environment. A new version writes `docs/project/releases/<version>.json`: `schema`, `version`, `env`, `envs`, `from`, `to` (full SHAs), `commits` (the count in `from..to`), `items` (the IDs in those commits' `Work-Item` trailers; an ID mentioned in prose does not count), `date` (UTC), `by` and `agent`. Every call appends one line to `docs/project/deploys.jsonl` (`schema`, `version`, `env`, `from`, `to`, `date`, `by`, `agent`), which the installer marks `merge=union` in `.gitattributes`.<br>- `--from` defaults to the commit last deployed to that env, else the newest record of any env, else the whole history.<br>- The same version at the same commit in another env is a promotion: one more ledger line, one more entry in `envs`. At a different commit it is refused; a version is never rewritten.<br>- `by` is the person: `--by`, else `git config user.name`, else `null`. `agent` is the tool (`AI_SDLC_AGENT` or the harness). Email addresses are never stored, and `--by` refuses one.<br>- A version is letters, digits and `. _ + -` (up to 64, no `..`); an env is lower-case letters, digits, `_` and `-` (up to 32). A ref that starts with `-` or names no commit is refused. Exit `1` on a refusal, with nothing written. |
| **`deploy list`** | `--json` | Which version runs in each environment: the newest ledger line per env, with its date, commit and who deployed it. A malformed ledger line is skipped and counted. The viewer's Dashboard shows the same table in its **Environments** card. |
| **`parallel`** | `--sync-refs`, `--json` | Groups unclaimed Ready items with finished dependencies so no two in a group touch overlapping files (from item `touch` globs, plan *Files that change*, or spec deltas; Tier 1 items still require a written plan). |
| **`dispatch`** | `--workers N`, `--by <agent>\|cmd:<cmd>` (any agent record with build argv: claude, codex, gemini, opencode, kiro, ...), `--model`, `--reviewer`, `--max-items`, `--tier`, `--max-retries`, `--pr`, `--no-merge`, `--sync-refs`, `--dry-run`, `--json` | Executes conflict-free waves of Ready items across isolated git worktrees using a headless builder CLI, runs `verify` (with bounded repair retries), optional independent `review`, and single-shot `finish`, merges completed Tier 2/3 branches (or opens PRs with `--pr`), and writes telemetry to `.ai-sdlc/dispatch/`. |
| **`mcp`** | `--allow-verify` | Serves the records to Claude Code and other MCP clients: JSON-RPC 2.0 over stdio, one message per line (`initialize`, `tools/list`, `tools/call`, `ping`). The tools are read-only: `item_list` (optional `status`, `tier`), `item_show`, `doctor`, `finish_status` (what `finish --dry-run` says is owed) and `status` (counts by status, open items, claims, `sync`). `verify` (runs `verify --item <ID>` and returns its summary) is offered only with `--allow-verify`, because it writes evidence. `finish`, waivers, `release` and extension commands are never exposed.<br>An `id` must match `^[A-Z][A-Z0-9]*-[0-9]+$` before it is used; each tool runs `sdlc.py` with a fixed argument list and no shell. Tool output is capped at 64 KB with control characters stripped. Only JSON-RPC goes to stdout; diagnostics go to stderr. `install.sh <dir> --mcp` registers it in `.mcp.json`. |
| **`audit`** | `--strict`, `--timeout`, `--json` | Runs the charter's `scan` stage in its JSON form (npm/pnpm/yarn audit, pip-audit, osv-scanner, cargo audit, govulncheck). It keeps the vulnerable packages under `.ai-sdlc/evidence/<stamp>-audit/` for the lens. The kit fetches nothing itself. |
| **`metrics`** | `--json`, `--env <env>` | Calculates quantitative project health metrics: work-in-progress (WIP), verification pass rate, cycle time, lead time, time waiting on humans, lifecycle record gaps, and usage against the charter's optional agent budget per tier. It also reports the four DORA delivery measures over the last 90 days: deploy frequency and lead time for changes (from the `deploy record` ledger and commit dates), change failure rate (deploys followed within 7 days by a hotfix or defect item) and time to restore (hotfix or defect items, open to Done). `--env` picks the environment; the default is `production`, `prod`, `prd` or `live`, else the only one on record. A measure without the records says `not enough data`. |
| **`log`** | `--since <ref>`, `--id <ID>`, `--write` | Drafts worklog lines, one per work item, from the commits since `<ref>` (IDs from subjects or `Work-Item` trailers) and the verify runs recorded on them. `--id` drafts one item's line, from just before its first commit unless `--since` says otherwise. `--write` inserts them under the worklog's marker, newest first, skipping items the worklog already names. Records become byproducts, not essays. |
| **`bite`** | `--base`, `--timeout`, `--restore`, `--json` | Puts the changed product files (never tests, never the kit's paths) back to the base, runs the test command, and restores them. It passes only when the tests pass with the change and fail without it. A backup and marker under `.ai-sdlc/bite/` make an interrupted run recoverable with `--restore`, and the doctor flags one. |
| **`sync`** | `--fetch`, `--strict`, `--json` | Where the checkout stands: ahead of or behind its upstream and the default branch, an unfinished merge or rebase, unpushed work, with the next command for each. Changes nothing; `--fetch` runs `git fetch --prune` first. Exit 1 on a `STOP` line; `--strict` also on a branch behind the default branch. Rules: `process/05-change-control.md`, "Staying in step with the remote". |
| **`trailers <ID>`** | `--agent`, `--model` | Prints the `Work-Item`, `Agent` and `Model` commit trailers, from flags, `AI_SDLC_AGENT` / `AI_SDLC_MODEL`, or what the harness exposes. |
| **`review <ID>`** | `--role`, `--by claude\|codex\|gemini\|cmd:<command>`, `--model`, `--stage design\|ship\|retro` | Sends one role's playbook, the item's diff, the relevant charter rows and the tier to another harness, headless, and saves the review with the reviewer's and author's identity, labelled independent or self-check. |
| **`config`** | `--effort`, `--independent-review`, `--tier-rules`, `--decision-style`, `--dev-method`, `--specs`, `--slop-filter`, `--discovered-defects`, `--reviewer`, `--token-saving`, `--set-check`, `--allow-extension ID`, `--worktree-scripts`, `--notify-webhook NUHUT_VAR\|off`, `--json` | Inspects or atomically updates kit constraints in `docs/project/charter.md` and syncs `.ai-sdlc/profile.json`. `--worktree-scripts "setup: <cmd>; teardown: <cmd>"` (or `none`) sets the Concurrency table's Worktree scripts row that `claim`, `unclaim --remove-worktree` and `dispatch` run; see [multi-agent.md](multi-agent.md#worktree-scripts). `--token-saving on` switches to `Lean` effort, `Independent review required for: none`, `Standard` tier rules, and compact tier budgets in one step. `--allow-extension <id>` adds the id to the charter's **Extensions allowed** row; it takes effect once that change is on the default branch. `--notify-webhook NUHUT_WEBHOOK_URL` writes the **Notify webhook** row with the name of the variable that holds the URL (never the URL); `off` turns it off. |
| **`notify`** | `--test`, `--ids-only`, `--json` | The webhook named by the charter's **Notify webhook** row, read from the default branch. With no flag it prints whether the row is on, the variable it names and whether that variable is set here (the scheme and host only). `--test` sends a `test` event and exits `1` when nothing was sent (row off, variable unset or refused, or the POST failed). Items set to Parked, a `finish` blocked by an escalated finding, and a Tier 1 `finish` send events on their own; a failure only warns. Guide: [extensions](extensions.md#webhook-notifications). |
| **`ext`** | `list`, `add <git-url\|path> [--ref REF]`, `update <id> [--ref REF] [--dry-run] [--yes]`, `remove <id>`, `search [term]`, `validate <path>`, `package <id> --for claude\|gemini\|codex\|kiro [--out DIR]`, `--json` (list) | Project extensions in `.ai-sdlc/local/extensions/<id>/`, recorded with their source, commit and file hashes in `.ai-sdlc/manifest.json` under `extensions`. `add` prints what the extension brings (data, and every executable entry point with its path) before it writes; `update` prints the old and new commit and the changed files (marking executable ones), backs up files edited here, and re-pins the hashes, asking first (or needing `--yes` without a terminal) when changed code of an allowed extension would run; `search` reads the catalog (`catalog.json`, or `NUHUT_CATALOG_URL`). `package` writes the plugin wrapper a tool expects (`.claude-plugin/plugin.json`, `gemini-extension.json`, `.codex-plugin/plugin.json`, or Kiro's `plugin.json` and `POWER.md`) from the manifest's `package` block into `dist/extensions/<id>/<tool>/`; no wrapper lists skills. Code runs only for ids the charter's **Extensions allowed** row lists. Guide: [extensions](extensions.md). |

### Where the agent tool tables come from

`review --by`, `dispatch --by`, `dispatch --reviewer` and `config --reviewer` take their
agent CLIs from the extension registry (`.ai-sdlc/bin/registry.py`). Each tool has one
`agents` record with its review argv, build argv, model flag, model family and the
environment variables `trailers` reads to name the agent and model, so the reviewer and
builder tables cannot disagree. `dispatch --reviewer` is checked against the review argv
it runs with. It reads `nuhut-extension.json` manifests from
`.ai-sdlc/local/extensions/<id>/` (the project's own) and `.ai-sdlc/extensions/<id>/` (the
built-ins: `core`, `claude`, `codex`, `gemini`, `cursor`, refreshed by `--upgrade`). The
installer reads the same built-ins for its `--harness` tables and presets.

- A project extension can add harness and preset records. It replaces a built-in record
  only when its manifest says `"overrides": "<built-in id>"` and **Extensions allowed**
  lists it, and then only that built-in's records, by id. Without `overrides`, a record that collides with a built-in
  is ignored and `doctor` says why.
- Executable contributions from a project extension (agent argv, check commands, hook
  rules, doctor checks, lifecycle hooks) load only when the charter's **Extensions
  allowed** row lists its id on the default branch, and only while its files match the
  hashes `ext add` pinned. An override of a built-in needs that row too. Otherwise
  `doctor` warns once per extension and says how to allow it. See
  [extensions](extensions.md).
- A manifest with a schema newer than 1, a `nuhut` range that excludes the running
  version, or a field of the wrong type is skipped. The runtime prints one stderr line
  naming the file and field, and `doctor` reports it at fail level. An unknown key under
  `provides` is a warning.
- If `.ai-sdlc/extensions/` does not exist (an install made before 6.0) or `registry.py`
  cannot be imported, the runtime uses the 5.x tables and `doctor` warns "registry
  missing, using v5 tables". `install.sh <project> --upgrade` restores them. The
  `--reviewer` choices fall back to a fixed list, so a broken registry cannot break the
  command line.
- The hook dialect of a built-in tool cannot be changed by an override: `hooks.py` answers
  `claude`, `gemini` and `cursor` in their built-in shapes even when a project extension
  overrides their harness records.

### The command table

Every subcommand is an entry in `sdlc.py`'s `COMMANDS` table, which maps the name to its
handler. Code that imports `sdlc.py` can add a command with
`register_command(name, handler, help=..., configure=...)`, or a verb of a noun-verb group
with `verb=` (for example `rollout start` and `rollout list`). The handler is called as
`handler(project, opts, parser)` and returns the exit code; `configure(subparser)` adds its
flags. A name that a core command already uses, or that another extension took, is refused
with `ValueError`. Registered commands appear under "Extension commands" in `sdlc.py --help`.

An extension adds commands through a `commands` record in its manifest,
`{"id": "<name>", "file": "<file>.py"}`. The file defines `register(add, runtime)` and calls
`add(handler, help=..., configure=..., verb=...)` for the one name its record gives.
`sdlc.py` loads these files only when the command line names something other than a core
command, so core commands and the merge driver never import extension code. A project
extension's commands load only when **Extensions allowed** lists it and its pinned hashes
match. A record named like a core command is ignored with a warning, and the core command
keeps running. See [extensions.md](extensions.md#add-a-command).

| Command | Key Flags | Description |
| --- | --- | --- |
| **`issues pull`** | `--state open\|closed\|all`, `--label L`, `--limit N`, `--repo OWNER/NAME`, `--dry-run`, `--json` | From the `github-issues` built-in extension. Reads issues with `gh issue list --json number,title,labels,url` and parks each issue that no item maps to as a new **Parked** item (`waiting_on: backlog owner`), with the issue number in the shard's `issue` field. A `bug` label makes it a `defect`. An issue titled `<ID>: ...` links that item instead. The issue body is never read. Titles are cut to one plain line with no `\|` or control characters. Needs `gh` installed and logged in; exits `1` with the install hint when it is missing. Guide: [extensions](extensions.md#github-issues). |
| **`issues push`** | `<ID>...` or `--all`, `--repo OWNER/NAME`, `--dry-run`, `--json` | Opens a GitHub issue (`gh issue create`) titled `<ID>: <title>` for each item you name, or with `--all` for every item that is not Done or Dropped and has no issue, and stores the number on the shard. With neither it lists the candidates and exits `2`. The issue body carries only the ID, type, tier and status. An item that already has an issue is skipped. |

## The installer: `./install.sh [dir] [PREFIX] [options]`

`./install.sh --help` shows the options on one page, `--help full` explains each,
`--list <what>` lists the values (harnesses, platforms, presets, types, skills, sections)
and `--explain <topic>` explains a concept. The ones you will use most:

| Option | Does |
| --- | --- |
| *(none)* | Guided setup: shows what it detected, asks what it cannot, writes nothing until you confirm |
| `--quick` / `--full` / `--sections <list>` | Ask the essentials / every question / only these sections |
| `-y` | No questions, every default (implied without a terminal) |
| `--preset solo\|team\|regulated` | Effort, decision style, method and tier rules together |
| `--harness <list>` | Which AI tools read it: claude, cursor, copilot, gemini, windsurf, cline, roo, amp, aider, all |
| `--specs on\|off` | Living specs of what the system does (default off) |
| `--slop-filter off\|on\|strict` | Hold prose to a no-AI-tells standard (default off); with `--upgrade`, turns it on for an existing install |
| `--hooks`, `--git-hooks [secrets]` | Enforcement: tool-call guards, and commit guards every tool and person inherits |
| `--mcp` | Register `sdlc.py mcp` as the `nuhut` server in `.mcp.json`, merged into an existing file and never replacing an existing `nuhut` entry. Read-only tools; add `--allow-verify` to its `args` to offer `verify` |
| `--deploy <list>` | Deploy platform checklists |
| `--profile compact` | Shorter documents for small models |
| `--dry-run` | List what would be written |
| `--upgrade [--adopt]` | Refresh the kit's managed files later; never touches project records |
